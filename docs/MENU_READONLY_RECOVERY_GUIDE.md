# LINE 個人圖文選單異常：唯讀診斷與人工恢復指引（未部署）

## 目前狀態
本分支僅新增管理員可見的「唯讀檢查選單異常狀態」與對應診斷 API。
- 需要 ADMIN_SECRET 驗證，且 RICH_MENU_RECOVERY_INSPECTION=enabled、RICH_MENU_TEST_MODE=enabled、單一白名單 user ID 正確。
- 由獨立 staging Redis 讀取原選單快照、測試操作紀錄、永久操作鎖是否存在。
- 使用 LINE Messaging API 個人選單 GET 確認目前結果，不寫入、刪除或解鎖。
- 僅顯示鎖是否存在，不顯示鎖 token。
- 其他好友、未授權帳號、缺失紀錄一律禁止進一步操作。

## 異常情境的安全處理規則
- 原有選單已顯示：記錄狀態並核對官方 LINE App。**不要直接移除永久鎖**：仍可能有先前延遲中的 LINE POST。
- 仍顯示測試選單：停止自動重試；人工查看操作紀錄並確認可安全還原。
- 顯示第三種選單：停止；不得覆蓋其他操作者設定。
- LINE 404、查詢逾時或回傳不完整：停止，不可推定沒有個人選單。
- 永久鎖存在：只表示有未完成或需審查的流程，不能單靠時間判定能解鎖。

## 真正解鎖前需要的人工審查（尚未實作自動解鎖）
1. 確認來源 LINE channel、帳號與原選單 ID；保留操作紀錄、時間及檢查結果。
2. 核對所有可能正在處理的 LINE POST 與第三方操作；只靠等待不足以排除延遲寫入。
3. 視情況人工決定停止測試、交由 LINE 官方管理介面修復，或執行受控還原。
4. 操作完成再次 GET 確認狀態，保留原始備份與稽核資料。
5. 不能直接從後台使用任意 ID 解鎖或覆寫，必要時由專業人員復核資料庫鎖定及紀錄。

## 注意事項
新檢查功能不會提供 LINE 寫入 API，也**不代表**目前已能安全進行正式單人選單測試。需要專用選單圖片、原選單確認、併發外部操作審查及獨立 staging 部署規劃。

此分支未合併 main、未部署、未設定新 Access Token，不更動正式 Webhook。
