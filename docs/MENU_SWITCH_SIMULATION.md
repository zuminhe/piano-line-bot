# 單人圖文選單切換／還原：模擬驗證分支

本分支新增 `lib/menu-switch-service.js`，建立帶鎖定、事前備份校驗、選單規格核對、啟用前意圖日誌及事後回讀確認的流程。另用假 LINE 與記憶體資料庫模擬正常切換、回復、他人變更、LINE 回傳不確定情境。

**重要：**目前僅供程式測試，尚未接上真實 LINE rich menu GET/POST 寫入介面、尚未在 admin 暴露啟用按鈕、尚未部署，也未使用任何正式 Token。

## 安全邊界
- 操作需單一白名單 `RICH_MENU_TEST_USER_ID`、`RICH_MENU_TEST_MODE=enabled`，及獨立的切換／還原開關。
- 必須先有經 GET 200 確認、已儲存在 staging Redis 的原個人選單快照。
- 只接受設定的非預設測試 menu ID，且必須查驗六格版面僅含左上角 LIFF action，並確認已上傳圖片。
- 操作前再次確認當前個人選單仍等於快照，否則拒絕。
- 寫入前先儲存還原日誌，操作後再次讀取 LINE 個人選單 ID 確認。
- 若網路逾時或未知結果，保留原快照及恢復紀錄，不標示成功。
- 還原前必須確認目前選單仍等於**本次專用測試選單**；若有變更，拒絕覆蓋。
- **注意併發風險：**目前鎖有 90 秒期限，尚未加入完整 fencing token、極端延遲與崩潰恢復審核。尚不可用於真實 LINE 改寫。

## 尚待完成
1. 建立及上傳圖片所需 API，並隔離專用 Rich Menu ID。
2. 實作並測試實際 LINE link 適配器；確認呼叫方式、錯誤處理、圖片 GET。
3. 擴充日誌的原子狀態轉移、崩潰中斷恢復、跨請求及併發一致性。
4. 人工審查後才接入管理後台及 staging Vercel；確認真實備份成功才可切換。
5. 測試完成驗證恢復後，關閉相關開關、移除 staging Token。

不得合併到 `main`，不得更動正式 Webhook。
